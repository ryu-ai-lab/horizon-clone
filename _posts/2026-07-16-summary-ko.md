## [Gemma 4 26B Runs at 5 Tokens/Sec on 13-Year-Old CPU Without GPU](https://www.neomindlabs.com/2026/06/08/running-gemma-4-26b-at-5-tokens-sec-on-a-13-year-old-xeon-with-no-gpu/) ⭐️ 8.0/10

A recent demonstration successfully ran the Gemma 4 26B language model at a usable speed of 5 tokens per second on a 13-year-old Intel Xeon CPU, notably without requiring a dedicated GPU. This achievement highlights significant progress in optimizing large language model inference for older, CPU-only hardware. This development is significant as it drastically lowers the hardware barrier for running powerful large language models locally, making advanced AI capabilities more accessible to individuals and organizations without high-end GPUs. It also suggests a future where sophisticated LLMs can be deployed on a wider range of existing devices, reducing reliance on costly cloud inference services. The demonstration specifically utilized the Gemma 4 26B model, which is a Mixture of Experts (MoE) architecture activating 4 billion parameters per token, allowing it to achieve 27B-class quality with the latency of a smaller model. This performance on a vintage CPU without a GPU was achieved through advanced optimization techniques like quantization and efficient memory management.

hackernews · neomindryan · 7월15일 15:34 · [커뮤니티 토론](https://news.ycombinator.com/item?id=48922434)

**배경 지식**: Large Language Models (LLMs) are AI models trained on massive text datasets to understand and generate human-like language. "Local inference" refers to running these powerful models directly on a user's own hardware, such as a personal computer, rather than relying on remote cloud servers. Achieving efficient local LLM inference on CPUs, especially older ones, typically involves optimization techniques like quantization, which reduces the precision of the model's weights to decrease memory footprint and computational demands.

## [uv 0.11.29 Released with CUDA 13.2 Support and Performance Boosts](https://github.com/astral-sh/uv/releases/tag/0.11.29) ⭐️ 8.0/10

uv version 0.11.29, released on 2026-07-15, introduces significant enhancements including official support for CUDA 13.2 with PyTorch, the addition of JSON output for the `uv tree` command, and optimized PyPy downloads using gzip-compressed artifacts. This update also brings various performance improvements and refined dependency resolution capabilities. This release is crucial for Python developers, especially those in AI/ML, as CUDA 13.2 support expands compatibility for PyTorch users, while the `uv tree` JSON output provides programmatic access to dependency graphs. The overall performance and resolution improvements solidify `uv`'s position as a faster, more reliable alternative to traditional Python package managers like `pip`. Key technical details include `uv` now preferring local artifacts over URLs when installing from `pylock.toml` and significant performance gains through reduced resolver work and extensive reuse of workspace discovery across multiple commands. Additionally, preview features like splitting OSV audit queries for services with package limits and applying fixed-version information more precisely enhance security auditing capabilities.

github · github-actions[bot] · 7월15일 18:44

**배경 지식**: `uv` is an extremely fast Python package installer and resolver, written in Rust, designed as a drop-in replacement for `pip`, `pip-tools`, and `virtualenv`. It aims to be a comprehensive project and package manager, offering significant speed and reliability improvements over traditional tools. `pylock.toml` is a standardized lock file format (PEP 751) used to record Python dependencies for reproducible installations, ensuring that the exact versions of packages are used across different environments. OSV (Open Source Vulnerabilities) audit queries refer to checking packages against the OSV.dev database for known security vulnerabilities, providing a machine-readable format for vulnerability data.
