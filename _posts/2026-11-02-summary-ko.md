## [Simon Willison Recommends Deleting `uv.lock` for Python 3.15 Dependency Errors](https://simonwillison.net/2026/Nov/1/delete-uv-lock-first/) ⭐️ 7.0/10

Simon Willison, a prominent developer, advises Python users to delete the `uv.lock` file as a primary troubleshooting step when encountering dependency resolution issues, particularly after upgrading to newer Python versions like 3.15. This action helps resolve conflicts where `uv.lock` might be pinning dependencies to versions incompatible with the new Python interpreter. This advice is significant for Python developers as it provides a practical and immediate solution to a common and frustrating dependency management problem, especially when adopting new Python versions or using the `uv` package manager. It helps maintain project stability and developer productivity by quickly resolving build failures caused by incompatible locked dependencies. The specific issue arises when `uv.lock` pins a dependency, such as `watchfiles==1.1.1`, which relies on `PyO3`, to a version that does not yet have a Python 3.15 wheel. This leads to an error indicating that the Python 3.15 interpreter is newer than `PyO3`'s maximum supported version (3.14), and deleting `uv.lock` allows `uv` to resolve compatible versions.

rss · Simon Willison · 11월1일 23:24

**배경 지식**: `uv` is an extremely fast Python package and project manager designed to replace tools like `pip`, `pip-tools`, and `virtualenv`, using a universal lockfile (`uv.lock`) to manage dependencies. `Maturin` is a tool used to build and publish Rust crates with Python bindings, often leveraging `PyO3`, which is a Rust library for creating Python modules. The interaction between these tools can lead to versioning conflicts when Python interpreters are updated.
